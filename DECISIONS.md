# DECISIONS.md — журнал принятых решений

Когда `SPEC.md` не покрывает какую-то ситуацию явно, Claude Code принимает решение сам (без вопросов пользователю) и записывает его сюда. Пользователь может откатить или скорректировать решение, увидев запись.

## Формат записи

```
### YYYY-MM-DD | <короткий заголовок>

- **Контекст:** в каком пункте/фазе возникла неопределённость, что именно неясно.
- **Решение:** что конкретно сделано (или выбрано).
- **Обоснование:** почему именно так — со ссылкой на §SPEC.md / принципы / альтернативы.
```

Записи добавляются снизу (новые — внизу), чтобы хронология читалась сверху вниз.

### 2026-05-17 | Phase 1, пункт 1.10 | Источник шрифтов

- **Контекст:** SPEC §1.2 фиксирует список ~20 шрифтов, §6.8 показывает, как их загружать через FontFace из `app://fonts/<file>`. Откуда брать сами `.woff2` — спека не указывает.
- **Решение:** Используем **fontsource.org R2 CDN** (`https://r2.fontsource.org/fonts/<slug>@latest/<subset>-<weight>-<style>.woff2`). Скрипт `scripts/download-fonts.ts` качает все варианты в `resources/fonts/`. Имена сохранённых файлов: `<Family>-<weight>-<style>-<subset>.woff2`.
- **Веса:** 400 normal + 700 normal для всех; 400 italic — для пропорциональных рабочих шрифтов; моноширинные (Roboto Mono, JetBrains Mono) — только normal.
- **Подсеты:** latin + cyrillic (по §1.2 — «все с кириллическими сабсетами»). Lato, Poppins, Roboto Mono — только latin, у них нет официальной кириллицы на fontsource.
- **Альтернатива, рассмотренная и отвергнутая:** ставить fontsource как npm-пакеты (`@fontsource/roboto` и др.) и копировать из `node_modules` — раздуло бы node_modules на ~200 МБ и привязало бы к npm-релизам fontsource.
- **Обоснование:** fontsource — MIT, без регистрации, стабильный CDN, поддерживает прямые woff2-ссылки. Скрипт идемпотентен (skip if exists), безопасно запускать повторно.

### 2026-05-18 | Phase 2, пункт 2.13 | Объём Fill / Stroke / Opacity-секций Inspector-а

- **Контекст:** §12 п.2.13 = «Inspector: fill (solid + gradient picker), stroke, opacity». Spec не уточняет, сколько gradient stop-ов поддерживать, какую палитру по умолчанию, как трактовать `color: 'red'`-имена и т. д.
- **Решение:**
  - **Gradient: 2 фиксированных stop-а** (`pos=0` «From», `pos=1` «To»). Многостоповый редактор — отдельная итерация улучшения, не в 2.13.
  - **Color input:** свотч (нативный `<input type="color">`) + hex-input. Нормализатор строго принимает `#rrggbb` / `#rrggbbaa` (lowercase). CSS-имена цветов (`red`, `blue` и т. д.) схема всё ещё разрешает (`colorSchema` шире), но через UI они не вводятся — это упрощает дальнейший pptx/gslx round-trip.
  - **Stroke dash:** три пресета — Solid / Dashed `[8,4]` / Dotted `[2,4]`. Кастомный массив — Phase 2.13-extension.
  - **Opacity = 1:** записываем `undefined` в модель (рендереры читают `opacity ?? 1`), не пишем `1` явно — чище JSON.
  - **Image-fill:** в селект режима в 2.13 НЕ добавляем; включится в Phase 3.19 (media).
- **Обоснование:** все четыре сужения дают рабочий и предсказуемый MVP-UI, не закрывая дорогу к расширению (схема уже всё это поддерживает).

### 2026-05-19 | Phase 2, пункт 2.16 | Smart guides MVP scope

- **Контекст:** SPEC §6.10 даёт алгоритм (6 anchor-ов на объект, threshold = 6/zoom, rbush при N > 500), но не специфицирует визуальное оформление, поведение при multi-drag, длину направляющих, что считается «другими» (только фигуры или ещё края слайда).
- **Решение (MVP в 2.16):**
  - **Anchors**: 6 на фигуру (left/centerH/right + top/centerV/bottom) — строго по спеке.
  - **Threshold**: 6 px на экране → `6 / zoom` в координатах слайда.
  - **Алгоритм**: O(N×M) перебор без rbush (фигур десятки, не сотни — для N>500 добавим spatial index в Phase 3).
  - **Что снепаем**: все остальные фигуры на слайде + сам слайд (как bbox с anchors на краях и центрах). Snap к центру слайда даёт «центрирование объекта» автоматически.
  - **Multi-drag**: snap считается относительно **union-bbox** перемещаемой группы, дельта применяется ко всем. И для ShapeNode group-drag-а, и для Canvas custom multi-drag (тяга за пустое место внутри bbox).
  - **Визуально**: одиночная розовая линия (`#ff4081`) на всю ширину/высоту слайда, рисуется на selection-layer. Линии между min/max парами (как в Slides) — задача полировки, отложил.
  - **Стор**: отдельный `useGuidesStore` — изменения guide-ов не дёргают остальной UI.
- **Что НЕ в 2.16:** resize-snap (пока snap только на drag), equal-spacing guides («одинаковые расстояния между фигурами»), snap к anchor-ам на анкорах Transformer-а, отключение через клавишу-modifier.

Заодно подключил уже существующие пункты `view:toggle-grid`, `view:toggle-ruler`, `view:zoom-*` — раньше они не доходили до UI вообще.

### 2026-05-19 | Phase 2, пункт 2.20 | Group/Ungroup — flat groupId vs nested container

- **Контекст:** Группировка фигур может быть реализована как (a) вложенный container-узел (Group-shape с children-массивом, относительные координаты), либо (b) плоская модель с `groupId?: string` у каждой фигуры (одинаковый id → одна группа).
- **Решение:** Вариант (b) — плоский `groupId`. Группировка влияет только на логику выделения (`expandToGroups`): клик по любой фигуре группы выделяет всех её членов.
- **Обоснование:** (a) требует рекурсивного рендера, координат относительно родителя, особой логики при resize/rotate группы. (b) минимально инвазивен — рендерер не знает про группы, drag/copy/align работают как раньше; новый groupId генерируется при `Cmd+G`. Это подходит для MVP; вложенные группы и трансформации группы целиком (rotate-вокруг-центра-группы) можно добавить в Phase 3.

### 2026-05-19 | Phase 2, пункт 2.21 | Clipboard — внутренний, без OS-pasteboard

- **Контекст:** §12 п.2.21 — «Copy / Paste / Cut / Duplicate». Спека не уточняет, идём ли через системный буфер обмена (Pasteboard / Windows clipboard) или внутренний.
- **Решение:** На Phase 2 используем **внутренний** `useClipboardStore` — массив фигур в памяти приложения. Интероп с PowerPoint/Keynote через OS-clipboard (XML-сериализация Office Open) — Phase 5.
- **Side-effects:**
  - При paste новым фигурам присваиваются свежие UUID; `groupId` re-map'ится, чтобы копия группы оставалась группой (но отдельной от оригинала).
  - Offset вставки = +20 px по обеим осям (как в Slides).
  - Cut = Copy + Delete; Duplicate = sourceShapes → push с offset, не трогая clipboard (как в Slides по Cmd+D).
- **Обоснование:** Внутренний буфер избегает зависимости от OS API на этом этапе, и интероп всё равно требует особого формата (OpenXML / SVG). Делать «полу-OS-clipboard» с plain JSON смысла нет.

### 2026-05-19 | Phase 2, пункт 2.23 | Undo — snapshot-based с дебаунсом 300ms

- **Контекст:** SPEC §11 / §12 п.2.23 упоминает `produceWithPatches` (immer patches). Patches компактнее, но требуют рефакторинга всех ~15 callsite-ов `useDeckStore.setState`, либо кастомного middleware вместо стандартного immer-middleware.
- **Решение:** Snapshot-based. `useDeckStore.subscribe` ловит изменения, через 300 ms тишины кладёт **предыдущий** Deck в `past`. Cmd+Z → восстановить из past, текущий → в future. Глубина 100 шагов.
- **Преимущества:** один subscribe-callback, не трогаем call-site-ы. Immer reuses immutable sub-trees → snapshot фактически разделяет память с текущим состоянием. Дебаунс 300ms сжимает drag-burst (60 fps мутаций) в один шаг.
- **Игнорируем** переходы null↔Deck (создание дека при первом старте, File→Close): Cmd+Z до упора не должен оставлять приложение без активного слайда («Активный слайд не найден»).
- **Минус:** не различаем «логические» транзакции (drag, цвет в Inspector, paste) — все объединяются в один шаг по таймауту 300 ms. Если пользователь быстро меняет несколько свойств подряд, undo откатит всё разом. Приемлемо для MVP.
- **Переход на patches** возможен в Phase 3 (требует ввести middleware-обёртку над immer).

### 2026-05-19 | Phase 2, пункт 2.24 | Filmstrip thumbnail — упрощённый CSS вместо PNG-рендера

- **Контекст:** §6.9 описывает «правильный» thumbnail-pipeline: рендер слайда в OffscreenCanvas в Worker-е, кэш PNG в IndexedDB по `${slideId}_${contentHash}`. Это значительный объём работы (Worker setup, postMessage сериализация, IDB).
- **Решение (MVP в 2.24):** Filmstrip-item рендерит **упрощённое CSS-превью** — absolute-позиционированные `<div>`-ы с bg-fill / border-stroke каждой фигуры, координаты в `%` от размеров слайда. Эллипс получает `border-radius: 50%`. Текст / линия / path рендерятся как пустой rect с обводкой — приблизительно показывает «карту распределения объектов».
- **Виртуализация:** `react-virtuoso` — даже при 100+ слайдах рендерится только видимая часть filmstrip-а.
- **Drag-reorder:** HTML5 DnD (`draggable`, `dataTransfer`), insertion перед target. Не работает за пределами видимой части — но при 100+ слайдах это редкий кейс; «drag через скролл» можно добавить позднее.
- **Что отложено в Phase 3:** честный PNG-thumbnail через OffscreenCanvas + IDB-cache (§6.9 целиком).

### 2026-05-19 | Phase 2 extension | Text внутри произвольной фигуры (double-click)

- **Контекст:** §12 явно описывает только `TextShape` с собственным `tiptapDoc` (пункт 2.10). Slides/PowerPoint позволяют двойным кликом на любую фигуру (rect/ellipse/path) ввести текст «внутри» — это часть базового UX-ожидания.
- **Решение:** Добавляю опциональное поле `text?: unknown` (TipTap JSON) в `baseShape`. Любая фигура (кроме линии) по `onDblClick` открывает существующий `TextOverlay`. Для TextShape он по-прежнему пишет в `tiptapDoc`, для остальных — в `text`. Plain-rendering текста внутри фигуры — общий компонент `ShapeTextLabel` поверх Rect/Ellipse/Path.
- **Совместимость с будущим:** все TipTap-расширения (Bold/Italic/Color/FontSize/…) применяются к ОДНОМУ редактору в `TextOverlay` — следовательно, как только Inspector (Phase 2.13-ext / Format menu / Phase 2.35) научится посылать команды форматирования в активный TipTap-editor, форматирование автоматически заработает и для TextShape, и для текста-в-фигуре.
- **Что НЕ в этом расширении:** vertical-align внутри фигуры (по умолчанию center), auto-resize fontSize под bbox (Slides «Shrink text on overflow»), индивидуальные padding-ы — добавим в Phase 3 как часть «Advanced editing».

### 2026-05-19 | Phase 2 ext | Multi-drag через Canvas-level (не Konva native)

- **Контекст:** Konva native drag (`draggable` на Group) для одиночной фигуры работал, но для группы (когда selectedIds.length ≥ 2) давал «дрожь» при моих попытках двигать остальных императивно: React-рендер новых model-state-ов сталкивался с Konva-trackbox-логикой, плюс `SelectionTransformer` re-attach-ил ноды на каждый modifiedAt.
- **Решение:** В мульти-выделении (2+) у ShapeNode `draggable=false`. Multi-drag целиком на Canvas-уровне через `multiDragRef`: при mousedown на любой фигуре в multi-selection стартуем своё отслеживание pointer-а; на mousemove императивно двигаем все Konva-ноды + пишем позиции в стор. SelectionTransformer-эффект на modifiedAt был разделён: re-attach только на selectedIds-change, forceUpdate-only на modifiedAt — это сняло «дрожь» при live-обновлении стора.
- **Side-effects:** filmstrip и Inspector обновляются вживую во время multi-drag (потому что стор тикает каждый mousemove). React.memo на ShapeView + immer-sharing ссылок исключает re-render не-перемещаемых фигур.

### 2026-05-19 | Phase 2.24 ext | Filmstrip thumbnail через CSS-transform scale

- **Контекст:** Изначально рендерил каждую фигуру в filmstrip как `<div>` с `%`-координатами и font-size 6 px для текста. Получалось не пропорционально канвасу: текст обрезался, шрифт нечитаемый. Альтернатива — PNG-thumbnail через OffscreenCanvas (§6.9, Phase 3+).
- **Решение:** В FilmstripItem-е рисую внутренний слой размером 1920×1080 (real slide-coords) и применяю `transform: scale(THUMB_W / slideW)` на родителя. Фигуры рендерятся с настоящими `x/y/w/h`, шрифт — родной 20 px. После scale-а на ~0.07 получается миниатюрное превью пропорциональное канвасу. Path рендерится через `<svg><path>` с `vector-effect: non-scaling-stroke`, чтобы штрих не утолщался от scale.
- **Не реализовано:** Реальный PNG-thumbnail через OffscreenCanvas+Worker + IndexedDB-cache (§6.9) — большая работа, отложена в Phase 3+.

### 2026-05-19 | Auto-fit zoom на старте и Cmd+0

- **Контекст:** Дефолтный `zoom = 1` при canvas-области < 1920×1080 (типичный случай) делал слайд больше канваса — пользователь не видел границ слайда, всё казалось «белым». Slides и PowerPoint при открытии fit-ят слайд под окно с отступом.
- **Решение:** В Canvas auto-center-эффект подбирает `fitZoom = min(stageW/slideW, stageH/slideH) * 0.95`, ставит pan по центру. Срабатывает пока `userMoved=false`. Cmd+0 / меню «Сбросить масштаб» возвращает `userMoved=false` → fit повторяется.

### 2026-05-19 | Cmd+A — выделение фигур, не текста браузера

- **Контекст:** В меню «Правка → Выделить всё» был `role: 'selectAll'` — вызывает `webContents.selectAll()`, выделяет произвольный текст на странице (URL, header, плейсхолдеры). Пользовательский ожидал — выделить все фигуры активного слайда.
- **Решение:** Меню → custom click `edit:select-all`. `useShapeClipboard` слушает Cmd/Ctrl+A и вызывает `selectAll()` из `lib/clipboard.ts`, который выделяет `slide.shapes.map(s => s.id)`. Внутри text-input / contenteditable Cmd+A работает нативно (выделяет текст поля) — наш хук пропускает.

### 2026-05-19 | macOS ApplePressAndHoldEnabled=false

- **Контекст:** macOS по умолчанию на удержание буквы показывает picker диакритик (é, è, ê...). Это перехватывает auto-repeat и пользователь не мог «зажать» клавишу для повтора ввода в TipTap.
- **Решение:** В `src/main/index.ts` до `app.whenReady()`: `systemPreferences.setUserDefault('ApplePressAndHoldEnabled', 'boolean', false)`. Применяется к app-defaults; вступает в силу со следующего запуска. Picker диакритик в нашем приложении отключён, key-repeat работает нативно.

### 2026-05-19 | Phase 2.28 | Background editor: data URL для image, scope = слайд/все

- **Контекст:** `SPEC.md` §12.2.28 формулирует пункт коротко: «Background editor (color/image/reset)». §1.6: «Фон слайда: цвет / изображение / сброс к теме». Открытые вопросы: (1) где хранить выбранный image-файл — MediaManager (§6) реализуется только в Phase 3; (2) scope применения — текущий слайд или все.
- **Решение:**
  - Image хранится как **data URL прямо в `slide.background.src`**. Схема `slideBackgroundSchema` уже принимает `z.string()`, а Konva.Image грузит data URL без проблем. MediaManager в Phase 3 заменит data URL на ссылки `media/<hash>.<ext>`; в момент миграции достаточно одного прохода по слайдам, схема не меняется.
  - **Scope** = выбор пользователя: модалка предлагает две кнопки — **«Применить»** (только активный слайд) и **«Применить ко всем»** (вся дека). Это типичный UX Slides / PowerPoint. Третья кнопка — «Отмена». «Сброс» сделан отдельной вкладкой **«По теме»**: применяет `{ type: 'theme' }`.
  - **Размещение модалки** повторяет `LayoutPicker`: state в `App.tsx`, команда `slide:background` (уже отправляется из меню) триггерит open. Esc + outside-click закрывают без apply. Подписки на стор активного слайда инициализируют форму при открытии.
- **Side-effects / ограничения:**
  - На канвасе bg-image рендерится через `react-konva` `Image` с `useBackgroundImage`-хуком (HTMLImageElement onload). В filmstrip — через CSS `background-image: url(data:...)`, чтобы не плодить асинхронных загрузок в превью.
  - Image-fill **shape-ов** (Inspector → Заливка → Изображение) остаётся Phase 3.19 — этот пункт только про **фон слайда**.
  - Большие изображения как data URL раздувают `deck.modifiedAt`-сериализацию (история, .gslx). Принимаем — Phase 3 (MediaManager) уберёт.

### 2026-05-19 | Phase 2, пункт 2.29 | Slide size dialog: пресеты, единицы, поведение содержимого

- **Контекст:** §12 п.2.29 = «Slide size dialog (4:3, 16:9, custom)». §1.1: «Размер слайда: 4:3, 16:9, 16:10, кастом в дюймах/см/pt/px». Не уточнено: (1) точные пиксельные размеры пресетов, (2) что делать с фигурами при смене размера, (3) куда повесить меню.
- **Решение:**
  - **Пресеты (px @96 DPI):** 16:9 = **1920×1080** (FullHD, наш дефолт), 4:3 = **960×720** (10×7.5 in — стандарт PowerPoint/Slides Standard), 16:10 = **1280×800** (10×6.25 in), Custom.
  - **Единицы:** px / in / cm / pt. Внутри модели и в схеме `deck.size` — **всегда px**. Конверсия делается строго в UI-слое `SlideSizeDialog`. Переключение единиц в модалке конвертирует уже введённое значение через px (не сбрасывает ввод).
  - **Лимит:** ≤ 32000 px по каждой стороне — Konva упирается в лимит HTML canvas (~32767 px), брать с запасом.
  - **Содержимое при смене размера:** чекбокс «Масштабировать содержимое всех слайдов», по умолчанию **включён**. Раздельные коэффициенты `sx = newW/oldW`, `sy = newH/oldH` применяются к `x/y/w/h` всех фигур всех слайдов. fontSize пока не масштабируем (он in slide-coords и читается пропорционально zoom-у canvas — большие изменения соотношения сторон могут потребовать ручной правки шрифта).
  - **Меню:** «Файл → Размер слайда…» (как Google Slides → File → Page setup), между «Сохранить как…» и «Экспорт». Команда `file:slide-size`. Модалка живёт в `App.tsx` рядом с LayoutPicker / BackgroundEditor.
- **Что НЕ в 2.29:**
  - Масштабирование fontSize (только x/y/w/h).
  - Сохранение пропорций при изменении одной стороны (lock-aspect toggle) — добавим, если будет запрос.
  - Авто-перекомпоновка layout-placeholder-ов под новый размер (это задача 2.27/Phase 3 master).
- **Обоснование пресетов:** 1920×1080 уже стоял по дефолту во всём проекте; 960×720 и 1280×800 — стандартные «10-inch» размеры из PowerPoint, естественные при экспорте в .pptx (Phase 5). Альтернатива 1280×720 для 16:9 отвергнута — у нас уже все layout-ы и тесты под 1920×1080.
